Assignment: Real-Time Data Pipeline Architecture & Anomaly Detection System for Enterprise POS (ทำสไลด์ และ Demo นำเสนอ วันที่ 15 ก.ย. 69)  ส่ง Link video presentation เฉพาะ Task 1-4 
วัตถุประสงค์ (Learning Objectives)
ประเมินและเลือกใช้เทคโนโลยีสำหรับ Event-Driven Data Pipeline ได้อย่างเหมาะสม
ออกแบบระบบที่มีความทนทานต่อความผิดพลาด (Resilience) และรองรับคุณสมบัติ Idempotency
วิเคราะห์ Performance Trade-offs ระหว่างสถาปัตยกรรมรูปแบบต่างๆ
โจทย์และภารกิจที่นักศึกษาต้องทำ (Assignment Tasks)
Task 1: Advanced Workload & Edge Case Generation (ทดลองในระบบจริงให้ดู)
พัฒนา Python Script ให้จำลองสถานการณ์จริงในระบบ POS เพิ่มเติมจากสภาวะปกติ เช่น
Flash Sales: ยอดขายพุ่งสูงขึ้น 10 เท่าชั่วขณะ
Network Latency: ข้อมูลส่งมาล่าช้ากว่าเวลาจริง (Late-Arriving Data)
Data Quality Issues: มี Transaction ID ซ้ำซ้อน หรือค่า Total Amount ติดลบ
Task 2: Resilient Airflow Ingestion Pipeline
Resource Optimization: บังคับใช้ Deferrable Operators (Triggers) แทน FileSensor แบบดั้งเดิม เพื่อวัดประสิทธิภาพการคืน Worker Slots
Idempotency & Data Cleanse: ออกแบบ SQL Query (ON CONFLICT DO UPDATE/NOTHING) ใน PostgreSQL เพื่อให้รัน DAG ซ้ำกี่ครั้ง ข้อมูลก็จะไม่ซ้ำซ้อน
Dynamic Alerting: เพิ่มระบบแจ้งเตือนอัตโนมัติ (เช่น Line Notify, Telegram หรือ Slack Webhook) เมื่อพบ Anomaly ในข้อมูล
Task 3: Live Analytics Dashboard & Secure Deployment
สร้าง Streamlit Dashboard ที่ไม่เพียงแค่โชว์ยอดรวม แต่ต้องคำนวณ Moving Average (ยอดขายเฉลี่ยเคลื่อนที่) และไฮไลต์ธุรกรรมที่เป็น Anomaly
Task 4: Architectural Report & Performance Analysis (รายงานเชิงวิชาการ)
Benchmark Report: เปรียบเทียบการใช้ Resource (CPU/Memory/Worker Utilization) ระหว่าง FileSensor (mode='poke'), FileSensor (mode='reschedule') และ Deferrable Operator
Scalability Proposal: เขียนข้อเสนอเชิงสถาปัตยกรรม หากต้องขยายระบบรองรับ 10,000 Transactions/วินาที จะเปลี่ยนส่วนประกอบใดบ้าง (เช่น เปลี่ยนจาก File Landing เป็น Apache Kafka และเปลี่ยน Postgres เป็น Columnar DB)
